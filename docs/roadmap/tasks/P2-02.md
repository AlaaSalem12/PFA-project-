## Read only
- `src/modules/assistant/assistant.service.ts` (the `AssistantTool` interface).
- The function signatures you reuse in: `src/modules/machine/machine.service.ts`, `src/modules/work-order/work-order.service.ts`, `src/modules/maintenance-plan/*service.ts`, `src/modules/employee/employee.service.ts`, `src/modules/dashboard/dashboard.service.ts`, plus `toMachineDto` and the work-order DTO mapper.

## Do
1. `src/modules/assistant/tools/`: one file per area (`machines.tools.ts`, `maintenance.tools.ts`, `hr.tools.ts`, `account.tools.ts`), plus `registry.ts`.
   - Each tool: `{ name, description, roles: Role[], args: zod schema, handler(ctx: {user: AuthUser}, args) }`.
   - The JSON schema sent to the LLM is built with `z.toJSONSchema(args)` (zod v4); strip `$schema`.
   - `registry.forUser(user)` returns only the tools that user's role is allowed.
   - `registry.run(user, name, rawArgs)`:
     - Re-checks the role → `{error: "not allowed"}`.
     - Validates args with zod → `{error: "<zod message>"}`.
     - Catches errors → `{error: "tool failed"}` (log the real error server-side).
     - Caps any array to 20 rows and adds `truncated: true` when it did.
2. Tools (read-only; reuse the services; output compact JSON with ISO dates; never include ids the user can't use, passwords, tokens, SSN, address, birthDate, phone):

   | name | roles | returns |
   |---|---|---|
   | `search_machines {query?, status?, type?, location?}` | all | code, name, type, status, location, nextMaintenanceDueAt |
   | `get_machine {code}` | all | specs + last 5 status changes + open work orders count + authorized operators (names) |
   | `get_fleet_summary {}` | all | counts by status and by type, overdue count, total |
   | `get_overdue_maintenance {}` | all | machines with daysOverdue, sorted desc |
   | `get_machine_history {code, limit≤20}` | all | status changes with who/when/comment |
   | `list_work_orders {status?, priority?, machineCode?, mine?}` | all — EMPLOYEE is forced to `mine` | #id, machine code, type, priority, status, assignee name, openedAt, closedAt |
   | `get_maintenance_plans_due {days≤60}` | ADMIN, PRODUCTION_MANAGER, MAINTENANCE_TECH, HR_MANAGER (same read roles as `/maintenance-plans`) | machine code, task, nextDueDate, frequencyDays |
   | `search_employees {query?, department?, status?}` | ADMIN, HR_MANAGER | matricule, full name, department, position, status, hireDate |
   | `get_hr_summary {}` | ADMIN, HR_MANAGER | headcount total, by department, by status |
   | `get_user_stats {}` | ADMIN | users by role, disabled, locked, never logged in |
   | `get_my_profile {}` | all | own name, role, linked employee (matricule, department, position), my open work orders count, unread notifications |

3. Descriptions are written for the LLM: when to use the tool, every argument with its allowed enum values, and that `code` means a machine code such as "CNC-001".
4. Wire the registry into `assistant.service.ts` (replace the empty placeholder).
5. Tests (`src/__tests__/assistant-tools.test.ts`, mocked Prisma via the existing helpers):
   - EMPLOYEE's tool list has no HR/user tools; calling `search_employees` as EMPLOYEE → `{error: "not allowed"}`.
   - Invalid args → `{error}`.
   - `search_employees` output keys never include socialSecurityNumber/address/birthDate/phone.
   - `list_work_orders` as EMPLOYEE ignores `mine:false`.
   - Arrays are capped at 20.
