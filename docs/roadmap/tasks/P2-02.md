# P2-02 — Assistant tool catalogue
Repo: backend · Model: Sonnet · Priority: MUST · Depends: P2-01

## Read only
`src/modules/assistant/assistant.service.ts` (the `AssistantTool` interface), the machine/work-order/employee services (only the function signatures you reuse).

## Do
1. `src/modules/assistant/tools/` — one file per area, plus `registry.ts`.
   - Each tool: `{ name, description, roles: Role[], args: zod schema, handler(ctx: {user}, args) }`.
   - The JSON schema sent to the LLM comes from `z.toJSONSchema(args)` (zod v4).
   - `registry.forUser(user)` returns only allowed tools.
   - `registry.run(user, name, rawArgs)`:
     - Re-checks the role.
     - Validates args with zod.
     - Catches errors and returns `{error}`.
     - Caps results at 20 rows.
2. Tools (read-only; reuse existing services/Prisma; output compact JSON):
   | name | roles | returns |
   |---|---|---|
   | search_machines {query?, status?, type?, location?} | all | code, name, type, status, location, nextMaintenanceDueAt |
   | get_machine {code} | all | specs + last 5 status changes + open work orders count |
   | get_fleet_summary {} | all | counts by status and type, overdue count |
   | get_overdue_maintenance {} | all | machines with days overdue |
   | get_machine_history {code, limit≤20} | all | status changes with who/when/comment |
   | list_work_orders {status?, priority?, machineCode?, mine?} | all (EMPLOYEE forced mine) | only if the module exists |
   | search_employees {query?, department?, status?} | ADMIN, HR_MANAGER | matricule, name, department, position, status, hireDate (NO SSN/address/birthDate/phone) |
   | get_hr_summary {} | ADMIN, HR_MANAGER | headcount by department and status |
   | get_user_stats {} | ADMIN | users by role, disabled, locked, never logged in |
   | get_my_profile {} | all | own name, role, linked employee, my open work orders count |
3. Descriptions are written for the LLM: when to use the tool, and what each argument means (enum values listed).
4. Tests:
   - Role filtering: an EMPLOYEE never gets HR tools; running one by name anyway → `{error: "not allowed"}`.
   - Invalid args → `{error}`.
   - `search_employees` output has no sensitive keys.
