# P1-02 — Auth and rate-limit fixes
Repo: backend · Model: Sonnet · Priority: MUST · Depends: P1-01

## Context
The strict auth limiter (20/15 min) also counts `/me` and `/refresh`, which the SPA calls automatically. The global limiter (200/15 min/IP) is too low for a factory behind one NAT. Login is case-sensitive while usernames are stored lowercase. A locked account returns 423 (leaks existence) and unknown users skip bcrypt (timing leak).

## Read only
`src/app.ts`, `src/modules/auth/auth.routes.ts`, `src/modules/auth/auth.service.ts`, `src/modules/auth/auth.schemas.ts`. Contract §1.

## Do
1. Global limiter → 1000 per 15 min. Create `strictAuthLimiter` (10 per 15 min, key = IP) and apply it ONLY to `/login`, `/forgot-password`, `/reset-password`.
2. Schemas: `username` → `.trim().toLowerCase()`; emails in forgot-password → `.trim().toLowerCase()`.
3. `login()`:
   - Unknown/disabled/deleted user: still run `bcrypt.compare` against a constant dummy hash, then 401 "Invalid credentials".
   - Locked: 401 with message "Account temporarily locked. Try again later." and code `ACCOUNT_LOCKED`.
4. `refresh()`: rotate — increment `refreshTokenVersion` and return tokens signed with the new version (old refresh token stops working).
   Note: this also invalidates the old access token. That's fine because the frontend replaces both.
5. `DevelopmentMailService.sendPasswordReset`: when `NODE_ENV === "development"`, log the full reset link (`${FRONTEND_URL}/reset-password?token=...`) so it can be tested without SMTP. Never in production.
6. `me()`: include `employee: {id, matricule, firstName, lastName} | null`.

## Acceptance
- tsc + lint + tests pass. Update tests: login with "ADMIN" works; locked account → 401 + ACCOUNT_LOCKED.

## Don't
- Don't move tokens to cookies (out of scope). Don't touch user admin routes.
