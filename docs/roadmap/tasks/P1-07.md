# P1-07 — Work orders module
Repo: backend · Model: **Opus** · Priority: SHOULD · Depends: P1-06

## Context
The `WorkOrder` model exists but there's no API. Work orders are the "maintenance management" heart of the project: a breakdown → a corrective order → a technician fixes it → closed with cost and parts.

## Read only
`prisma/schema.prisma` (WorkOrder, Machine, Employee, Notification, User), `src/modules/machine/machine.service.ts` (for style), `src/common/*`. Contract §5 and §7 (notification types).

## Do
1. Schema migration `work_orders_v2`:
   - WorkOrder: add `resolution String?`, `createdById Int?` (relation to User "WorkOrderCreatedBy"), indexes on `[status]`, `[machineId]`, `[assignedToId]`. Replace the `createdBy String?` column.
   - NotificationType: add `WORK_ORDER_ASSIGNED`, `MAINTENANCE_DUE`.
   - Notification: add `workOrderId Int?` (relation, onDelete SetNull).
2. Module `src/modules/work-order/` (schemas, service, routes) mounted at `/api/v1/work-orders`. Endpoints, roles and transitions exactly as in §5.
   - EMPLOYEE: list is forced to `mine=true`; GET :id only if assigned to them.
   - `mine=true`: `assignedToId = req.user.employeeId` (if the user has no employee → empty page).
   - Assignee must be an ACTIVE employee. If the assignee has a linked user, create a WORK_ORDER_ASSIGNED notification (title "New work order #<id>", message "<machine code> – <priority> – <short description>").
   - DONE requires `resolution`. Set `closedAt`. `cost` ≥ 0.
   - Cannot edit a DONE order (409).
   - Cannot create a work order for a soft-deleted machine or one that is OUT_OF_SERVICE (409).
3. Serialize `cost` as a number. Include `machine {id, code, name}`, `assignedTo {id, firstName, lastName}`, `createdBy {id, fullName}`.
4. Audit WORK_ORDER_CREATED, WORK_ORDER_UPDATED, WORK_ORDER_STATUS_CHANGED.
5. Make `GET /machines/:id/work-orders` (from P1-04) use the same DTO mapper.
6. Seed: 6 demo work orders (mixed status/priority), assigned to the demo technician's employee.

## Acceptance
- tsc + lint + tests pass. Tests for: transition rules (OPEN→DONE rejected), DONE without resolution → 400, EMPLOYEE only sees own, assignment creates a notification.
