# P1-05 — Users module
Repo: backend · Model: Sonnet · Priority: MUST · Depends: P1-03

## Context
- The frontend form doesn't send `username` (backend requires it), so creating a user always fails.
- `HR_MANAGER` is missing from the zod role enums.
- With no SMTP configured, the admin never learns the temporary password.
- Users are mounted twice (`/users` and `/admin/users`).
- `resend-credentials` resets the password.
- `email.provider.ts` is dead code.

## Read only
`src/modules/users/*`, `src/common/safe-user.ts`, `src/app.ts`, `src/modules/mail/mail.service.ts`. Contract §2.

## Do
1. Create `src/common/roles.ts` exporting `roleSchema = z.nativeEnum(Role)` (or `z.enum(Object.values(Role))`). Use it in user schemas (and later everywhere).
2. Create: `username` optional. If missing, generate it from the email local-part: lowercase, keep `[a-z0-9._-]`, min 3 chars; if taken append `2`, `3`, ...
   Normalize email to lowercase on create AND update.
3. Response of create and reset-password: `{user, emailSent, temporaryPassword?}`. Include `temporaryPassword` only when `emailSent === false`.
4. `POST /users/:id/unlock` → clear `lockedUntil`, `failedLoginAttempts = 0`.
5. Remove the `resend-credentials` route and the `/admin/users` mount. Delete `src/modules/users/email.provider.ts` and update the test mock to mock `../modules/mail/mail.service` instead.
6. `employeeId` in create/update (number or null). Validate the employee exists and isn't linked to another user (409).
7. SafeUser adds `lockedUntil`, `createdAt`, `employee {id, matricule, firstName, lastName} | null` (include it in queries).
8. List filter `role` uses the shared enum, so HR_MANAGER now works.
9. Audit USER_UNLOCKED.

## Acceptance
- tsc + lint + tests pass. Tests:
  - Create without username → 201 with a generated username.
  - Create with role HR_MANAGER → 201.
  - With the dev mailer, `emailSent` is true. With a mailer that throws, `temporaryPassword` is present.
