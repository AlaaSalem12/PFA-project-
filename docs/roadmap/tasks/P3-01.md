## Do
Write Mermaid sources in `docs/report/diagrams/*.mmd`, then render PNGs (white background, scale 2) with `npx -y @mermaid-js/mermaid-cli -i X.mmd -o X.png -b white -s 2`:
1. `usecase-global.mmd`: actors Admin, HR manager, Production manager, Maintenance technician, Employee, LLM provider (external). Mermaid has no UML use-case type: use `flowchart LR` with actor nodes and rounded use-case nodes grouped in subgraphs per module.
2. `usecase-maintenance.mmd`, `usecase-hr.mmd`, `usecase-assistant.mmd`: detailed per module.
3. `class-diagram.mmd`: `classDiagram` from the Prisma models (main fields, enums, multiplicities).
4. `erd.mmd`: `erDiagram` from Prisma (tables + relations).
5. `sequence-login-refresh.mmd`: login, access token expiry, single-flight refresh.
6. `sequence-status-change.mmd`: tech changes a machine to BREAKDOWN → transaction (update, log, notifications) → admin bell.
7. `sequence-assistant.mmd`: user question → API → LLM → tool call → Prisma → LLM → answer saved.
8. `architecture.mmd`: browser → nginx (SPA, /api proxy) → Express API (modules) → PostgreSQL; API → LLM provider; uploads volume.
9. `deployment.mmd`: Windows host → VirtualBox VM (Ubuntu 24.04) → Docker Compose (web, api, db, optional ollama) with ports and volumes.
10. `docs/report/diagrams/README.md`: one line per diagram describing what it shows (used later for figure captions).
