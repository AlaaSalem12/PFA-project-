# P1-01 — Error handling
Repo: backend · Model: Sonnet · Priority: MUST

## Context
Prisma errors (duplicate key, record not found, FK violation) currently become 500. Every 4xx is labelled "Bad Request". Some routes answer with ad-hoc `{message}` bodies. CORS rejections become 500.

## Read only
`src/middlewares/error-handler.ts`, `src/common/api-error.ts`, `src/app.ts`, `src/middlewares/validate.ts`; then grep for `res.status(4` in `src/modules` to find ad-hoc responses.
Contract: API-CONTRACT.md §0.

## Do
1. `error-handler.ts`:
   - `error` = reason phrase from `http.STATUS_CODES[status]`.
   - Map `Prisma.PrismaClientKnownRequestError`: P2002 → 409 CONFLICT (message `"<field> already exists"` using `meta.target`), P2025 → 404 NOT_FOUND, P2003 → 409 CONFLICT ("Record is still referenced").
   - `PrismaClientValidationError` → 400 VALIDATION_ERROR.
   - Body-parser JSON syntax error (`type === 'entity.parse.failed'`) → 400.
   - Default `code` from status when not given (400 VALIDATION_ERROR, 401 UNAUTHORIZED, 403 FORBIDDEN, 404 NOT_FOUND, 409 CONFLICT, 429 RATE_LIMITED, 500 INTERNAL).
   - Never leak stack traces or Prisma messages for 500.
2. Unknown routes: add a 404 handler before `errorHandler` returning the same JSON shape.
3. CORS: reject with `new ApiError(403, "Origin not allowed", [], "CORS_REJECTED")`.
4. `app.set("trust proxy", 1)` (needed behind nginx in Phase 4).
5. Replace every ad-hoc `res.status(4xx).json({message})` in modules with `throw new ApiError(...)` (machine image, notifications, employee get).
6. Set the 429 handler of express-rate-limit to return the standard error JSON with code RATE_LIMITED (use the `handler` option; keep `Retry-After` header via `standardHeaders: "draft-8"`).

## Acceptance
- tsc + lint + `npm test` pass. Add tests in `src/app.test.ts`: unknown route → 404 JSON; mocked P2002 on user create → 409.

## Don't
- Don't change business logic or route paths.
