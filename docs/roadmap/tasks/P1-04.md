# P1-04 — Machines module fixes
Repo: backend · Model: Sonnet · Priority: MUST · Depends: P1-03

## Context
Known bugs:
- OUT_OF_SERVICE has no exit even for ADMIN (`transitions.OUT_OF_SERVICE = []`).
- `PUT /machines/:id` can change `maintenanceStatus` and bypass the state machine, history and notifications.
- The notification title says "out of_service" because it uses `.replace` instead of `.replaceAll`.
- Images are stored as base64 in the DB and returned in every list.
- Prisma Decimals are serialized as strings.
- Finishing maintenance doesn't reschedule the next one.
- Duplicate code → 500 (fixed generically in P1-01, verify here).

## Read only
`src/modules/machine/*`, `prisma/schema.prisma` (Machine model only), `src/app.ts`. Contract §4.

## Do
1. Schema: add `maintenanceIntervalDays Int? @map("maintenance_interval_days")` to Machine → `npx prisma migrate dev --name machine_interval`.
2. Transitions: `OUT_OF_SERVICE: ["UNDER_MAINTENANCE", "OPERATIONAL"]`, still ADMIN-only (keep the existing role check).
   On UNDER_MAINTENANCE→OPERATIONAL: set `lastMaintenanceAt = now` and, if an interval is set, `nextMaintenanceDueAt = now + interval days`.
3. `machineBodySchema`:
   - Remove `maintenanceStatus` and `imageUrl` from create/update bodies.
   - Add `maintenanceIntervalDays` (int 1–3650, optional).
   - Trim strings; empty strings → undefined.
4. Notification title: use `replaceAll("_", " ")`.
5. Images:
   - Store on disk with `multer.diskStorage` in `${UPLOADS_DIR}/machines` (env `UPLOADS_DIR`, default `uploads`; create the folder at startup). File name `<machineId>-<timestamp>.<ext>`.
   - Check magic bytes (JPEG FFD8FF, PNG 89504E47, WEBP "RIFF....WEBP"); reject otherwise with 400.
   - Delete the previous file when replacing it.
   - Save `imageUrl = "/uploads/machines/<file>"`.
   - Serve with `app.use("/uploads", express.static(UPLOADS_DIR, { maxAge: "7d" }))`.
   - Configure helmet `crossOriginResourcePolicy: { policy: "cross-origin" }` so the frontend on another port can load images.
6. Add a mapper `toMachineDto()` that converts Decimal fields to `Number` (or null). Use it in every machine response, including the dashboard's `machinesInBreakdown`.
7. Operators:
   - `GET /machines/:id` includes `authorizedOperators {id, matricule, firstName, lastName}`.
   - New `PUT /machines/:id/operators {employeeIds}` (ADMIN, PRODUCTION_MANAGER) using `set: ids.map(id => ({id}))`. Unknown ids → 400.
8. Add `GET /machines/:id/work-orders` (latest 50; returns `[]` until P1-07 adds fields — use the existing WorkOrder model).
9. Audit: MACHINE_OPERATORS_UPDATED.

## Acceptance
- tsc + lint + tests pass. Add tests:
  - PUT with `maintenanceStatus` is stripped or rejected.
  - Admin can move OUT_OF_SERVICE → OPERATIONAL; a technician gets 409.

## Don't
- Don't build work orders here (P1-07).
