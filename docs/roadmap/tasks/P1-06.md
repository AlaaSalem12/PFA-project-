# P1-06 — HR backend hardening
Repo: backend · Model: Sonnet · Priority: MUST · Depends: P1-05

## Context
- Employee and organization routes skip `requirePasswordChange`, have no filters, and return 500 on missing or duplicate records.
- Deleting a department that still has employees crashes.
- There's no lightweight endpoint to pick an employee (needed for work orders and user linking).

## Read only
`src/modules/employee/employee.routes.ts`, `src/modules/organization/organization.routes.ts`, `prisma/schema.prisma` (Employee, Department, Position). Contract §3.

## Do
1. Split employees into `employee.schemas.ts` + `employee.service.ts` + routes (same pattern as machines). Same for organization if it stays readable.
2. Middleware chain: `authenticate, requirePasswordChange, authorize(ADMIN, HR_MANAGER)`.
   Exception: `GET /employees/options` also allows PRODUCTION_MANAGER and MAINTENANCE_TECH. Register it BEFORE `/:id`.
3. List filters: `departmentId`, `positionId`, `status`, `search` (firstName, lastName, matricule, email). Sort allow-list.
4. `GET /employees/:id` includes `department`, `position`, `user {id, username, role}`, `authorizedMachines {id, code, name}`.
   Update/delete of a missing or soft-deleted employee → 404.
   Delete → 409 if OPEN/IN_PROGRESS work orders are assigned.
5. Zod: trim strings, email lowercase, `hireDate` required, `birthDate` before `hireDate`, phone `^[+0-9 ()-]{6,20}$`. Empty strings → undefined. `departmentId`/`positionId` accept null on update to clear.
6. Departments/positions: GET returns `employeeCount` (`_count`). DELETE → 409 when employeeCount > 0. Duplicate name → 409.
7. Audit actions per §9.

## Acceptance
- tsc + lint + tests pass. Tests: employee list filter by status; delete department with employees → 409; options endpoint as MAINTENANCE_TECH → 200.
