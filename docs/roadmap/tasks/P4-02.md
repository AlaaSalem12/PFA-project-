# P4-02 — Frontend image + deployment bundle
Repo: frontend · Model: Sonnet · Priority: MUST · Depends: P4-01

## Read only
`package.json`, `vite.config.ts`, `src/api/client.ts` (baseURL logic), `docs/roadmap/DEPLOY-VM.md` (what the user will run).

## Do
1. `Dockerfile` (multi-stage):
   - `node:20-bookworm-slim` build: `npm ci`, `npm run build` with `ARG VITE_API_URL=/api/v1`.
   - `nginx:1.27-alpine` serving `/usr/share/nginx/html` with `deploy/nginx.conf`.
   - `.dockerignore`.
2. `deploy/nginx.conf`:
   - SPA fallback `try_files $uri /index.html`.
   - `location /api/` and `location /uploads/` → `proxy_pass http://api:8080`, with `X-Forwarded-For/Proto/Host` headers.
   - `client_max_body_size 6m`. `proxy_read_timeout 120s` (assistant). `proxy_buffering off` for `/api/v1/assistant/`.
   - gzip on.
   - Long cache for `/assets/`, no-cache for `index.html`.
   - Security headers (X-Content-Type-Options, Referrer-Policy, X-Frame-Options DENY).
3. `deploy/docker-compose.yml` (release layout: build contexts `./backend` and `./frontend`):
   - `db` postgres:16-alpine: volume `pgdata`, healthcheck `pg_isready`, no published port.
   - `api`: build ./backend, `env_file: .env`, depends_on db healthy, volume `uploads:/app/uploads`, `restart: unless-stopped`.
   - `web`: build ./frontend, ports `"80:80"`, depends_on api, `restart: unless-stopped`.
   - `ollama` (profile `ai-local`): `ollama/ollama`, volume `ollama`, no published port.
4. `deploy/.env.example` with every variable, commented. Include:
   - `POSTGRES_USER/PASSWORD/DB`, and `DATABASE_URL` built from them with host `db`.
   - `JWT_SECRET`, `JWT_REFRESH_SECRET` (placeholder "CHANGE_ME_run_openssl_rand_hex_32").
   - `PORT=8080`, `NODE_ENV=production`, `CORS_ORIGIN=same-origin`, `FRONTEND_URL=http://CHANGE_ME_VM_IP`.
   - SMTP vars (empty). `SEED_ON_START=true`, `SEED_ADMIN_PASSWORD`.
   - LLM vars with the three provider examples commented, plus Ollama inside compose: `http://ollama:11434/v1`.
   - `UPLOADS_DIR=/app/uploads`.
5. `deploy/scripts/`:
   - `generate-env.sh`: copies `.env.example` → `.env` and fills secrets with `openssl rand -hex 32`, asks for the VM IP.
   - `backup-db.sh`: `pg_dump` to `backups/metalworks-<date>.sql.gz`.
   - `restore-db.sh`.
   - `pull-ollama-model.sh`.
   All `chmod +x`, LF line endings (add `.gitattributes`: `*.sh text eol=lf`).
6. `deploy/make-release.ps1` (Windows PowerShell, run from the frontend repo):
   - `git archive HEAD` of both repos (backend path `..\MetalHrBackend`) into `release\metalworks-release\{backend,frontend}`.
   - Copy `deploy\docker-compose.yml`, `deploy\.env.example`, `deploy\scripts\`, and `docs\roadmap\DEPLOY-VM.md` as `README-DEPLOY.md`.
   - Zip to `release\metalworks-release-<date>.zip`.
   - Refuse to run if either repo has uncommitted changes.
   - Add `release/` to `.gitignore`.
7. If Docker Desktop is available locally: extract the zip to a temp folder, `generate-env.sh` equivalent by hand, `docker compose up -d --build`, open http://localhost and log in. Report the result in PROGRESS.md.
